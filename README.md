# 清音交易所 · 应用恢复版

该项目包含浏览器交易端、管理后台和 Node.js API 服务。应用接入现有 Supabase 项目 `plukopgifmrlyjwqryqu`，使用其 Auth、行级权限、数据视图与业务函数。界面根据当前业务接口重新实现。现有数据库无需导入或迁移。

## 本地运行

需要 Node.js 20.12 或更高版本，无运行依赖。

```bash
cd qingyin-exchange
cp .env.example .env
npm start
```

Windows PowerShell 使用 `Copy-Item .env.example .env` 复制配置文件。示例配置已填写本项目的 Supabase URL 和可发布密钥。运行环境需能访问该 Supabase 项目的 HTTPS 地址。

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:3000/ | 现货行情、委托、钱包和站内消息 |
| http://127.0.0.1:3000/admin | 管理后台 |

使用现有 Supabase Auth 邮箱和密码登录。后台权限由数据库的 `admin_members` 决定。注册流程遵循该项目的邮箱确认配置。若项目要求邮箱确认，请完成邮件验证后再登录。公开部署时，在 Supabase Auth 中核对 Site URL 和回调白名单，生产环境通过 HTTPS 反向代理运行，并将 `APP_ORIGIN` 设为实际 HTTPS 地址、`COOKIE_SECURE` 设为 `true`。示例配置默认只监听本机。

## 在 GitHub Codespaces 试用完整应用

1. 将这个文件夹里的内容上传到 GitHub 仓库根目录，保留 `public/`、`test/`、`.github/` 和 `.devcontainer/` 的目录层级。
2. 在仓库页面选择 **Code → Codespaces → Create codespace on main**，等编辑器和终端加载。
3. 在 Codespaces 终端运行 `npm start`。Codespaces 启动后，服务会读取项目的可发布密钥和现有 Supabase 项目地址。如需自定义配置，可先将 `.env.example` 复制为 `.env`。
4. 打开编辑器底部的 **Ports**，找到 `3000`，点击转发地址旁的 **Open in Browser**。主页是交易端，地址后加 `/admin` 打开管理后台，`/healthz` 返回健康状态。

保持端口为 **Private**，先用自己的 GitHub 账号打开预览，再用清音交易所的 Supabase 账号登录。Codespaces 服务停止后，预览地址不会继续提供服务，再次打开 Codespace 后可运行 `npm start` 恢复预览。

GitHub Pages 支持发布静态网页。完整交易端和管理后台使用服务端会话及 API，并涉及登录与资金操作，使用 Codespaces 做私有试用和验收。现有 Supabase 数据库无需迁移。

## 支持的功能

| 模块 | 功能 |
| --- | --- |
| 现货交易 | 交易对搜索、行情、K 线、公开订单簿和成交、限价委托及撤单 |
| 钱包 | 可用和冻结余额、账本、站内转账、法币付款核实、银行账户绑定、提现申请和取消、入账记录 |
| 账户 | 邮箱注册与登录、账户和身份审核状态、站内消息 |
| 后台财务 | 账户查询、充值和提现审核、审计留痕的结算账户查看、站内记账额度分配和管理员账户转账 |
| 后台运营 | 资产登记、交易对创建和状态维护 |
| 后台合规与设置 | 审计、风控和身份审核记录、账户审核、客服、收款和法币提现配置 |

现有数据库在恢复时返回 10 个公开交易对和 9 个活跃资产，K 线、订单簿和成交为空。USDT 是站内记账单位。法币收款、法币提现和链上资金通道按数据库当前配置显示。提现审核通过表示等待付款处理。支付机构出款、链上广播和外部行情采集需要另有相应的服务和配置。

## 文件结构

- `public/` 交易端和管理端页面、样式及交互。
- `server.mjs` 提供网页、登录会话、数据查询和业务 API。请求以当前用户身份转发，由 Supabase 按角色和行级策略授权。
- `test/` 本地接口测试，使用测试替身。
- `.env.example` 本地部署示例。

压缩包内没有数据库内容导出、用户密码、服务端密钥或管理员凭证。
